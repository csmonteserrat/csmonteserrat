# Histórico de versões

## Versão 1.15 (tentativa de correção: PDF falhando no Safari macOS)

- **Reportado pelo usuário**: mesmo depois da v1.14, a importação de PDF continuava falhando — mas só no Safari (macOS 26.5.2); no Chrome funcionava normalmente. O erro específico (`undefined is not a function (near '...t of e...')`) é a formatação de erro característica do motor do Safari (JavaScriptCore) e apontava para dentro do próprio leitor de PDF (`pdf.js`), não para o código da ferramenta.
- **Ação tomada**: a versão do `pdf.js` empacotada (5.6.205, build "moderna") foi trocada pela build **"legacy"** da versão mais recente disponível (6.2.108) — variante que o próprio projeto `pdf.js` publica especificamente para navegadores com suporte mais restrito a recursos modernos de JavaScript/DOM, com polyfills adicionais. `assets/pdf.min.js` e `assets/pdf.worker.min.js` foram substituídos; a API usada pela ferramenta (`getDocument`, `GlobalWorkerOptions`, worker de módulo) continua idêntica, sem mudança de código em `app.js` além da própria substituição dos arquivos.
- **Limite importante**: este ambiente de desenvolvimento não tem como rodar Safari de verdade para confirmar a correção — só foi possível testar exaustivamente no Chromium (79/79 autotestes, os 4 arquivos reais de julho/2026 importando normalmente, e o fluxo de falha de importação). A troca para a build "legacy" é a correção mais indicada para esse tipo de erro segundo a documentação do próprio pdf.js, mas depende de confirmação do usuário no Safari real.

## Versão 1.14 (correção: importação de PDF falhando no Render)

- **Bug real corrigido: PDFs falhavam ao importar quando publicados no Render** (CSV continuava funcionando normalmente). Causa: o leitor de PDF (`pdf.js`) era carregado com `import()` dinâmico e um Web Worker de módulo a partir de arquivos com extensão `.mjs`. Nem todo host estático mapeia `.mjs` para um Content-Type de JavaScript por padrão — e como o navegador aplica checagem estrita de MIME type para scripts de módulo (e o `render.yaml` já define `X-Content-Type-Options: nosniff` para todas as rotas), o módulo é bloqueado silenciosamente e a importação de PDF falha, mesmo com o arquivo correto. Corrigido renomeando `assets/pdf.min.mjs` → `assets/pdf.min.js` e `assets/pdf.worker.min.mjs` → `assets/pdf.worker.min.js` (extensão `.js` é reconhecida como JavaScript por praticamente qualquer host). Confirmado localmente que o MIME retorna `text/javascript` e que os dois PDFs de amostra voltam a importar normalmente.
- **Bug real corrigido: o motivo de uma falha de importação nunca aparecia.** `importFiles` mostrava o erro específico de cada arquivo num toast, mas logo em seguida sempre disparava um segundo toast com o resumo ("X concluída(s) · Y falha(s)") no mesmo elemento — sobrescrevendo a mensagem real antes que desse para ler. Agora, quando há falha, abre uma janela listando cada arquivo com o motivo exato do erro, em vez de só o contador genérico.
- Adicionados 2 autotestes novos (78–79): o leitor de PDF referencia `.js` e não `.mjs`; a falha de importação guarda o motivo por arquivo em vez de deixar o resumo final sobrescrevê-lo. Total: 79 autotestes.

## Versão 1.13 (nada mais é salvo pelo navegador, a pedido do usuário)

Mudança de arquitetura pedida pelo usuário: o navegador deixou de guardar qualquer coisa entre uma abertura e outra da ferramenta. Todo o "salvar" passou a acontecer só na exportação manual do backup — se a aba for fechada ou recarregada sem exportar, tudo se perde, de propósito.

- **Removido todo o uso de IndexedDB.** Antes, a ferramenta salvava automaticamente uma cópia do estado no navegador (com debounce de 250ms a cada ação) e recarregava essa cópia sozinha na próxima visita. Isso foi totalmente removido: `openDB`/`dbGet`/`dbPut` não existem mais no código. O estado agora só vive na memória da aba enquanto ela estiver aberta.
- **Removida a função "Bloqueio local"** (senha que cifrava o estado salvo no navegador) — decisão tomada com o usuário: sem nada persistido no navegador, não sobrava o que essa senha protegesse. A proteção de dados agora é só a senha do arquivo de backup (que já existia e continua igual, cifrando com AES-GCM). Backups antigos que tinham bloqueio ativado são lidos normalmente; a migração só registra na auditoria que aquele campo foi descontinuado.
- **Novo aviso de "não salvo"**, visível o tempo todo, em três lugares: (1) um ícone no topo da tela que fica vermelho com um "!" quando há alteração não exportada; (2) o texto ao lado do contador de snapshots, que passa a dizer "Alterações não salvas — exporte um backup" em vermelho; (3) um cartão de destaque na tela de Configurações. Os três clicam direto para abrir o backup.
- **Aviso do próprio navegador ao tentar fechar ou recarregar a aba** (`beforeunload`) sempre que houver alteração não salva — o mesmo diálogo padrão de "sair sem salvar" que qualquer editor de documento usa.
- **Bug real corrigido, encontrado ao testar o aviso**: tanto exportar um backup quanto restaurá-lo chamavam `audit(...)` (que sempre marca "não salvo", corretamente, para qualquer ação) *depois* de já ter marcado o estado como salvo — então o próprio registro de auditoria da exportação desfazia a marcação de "salvo" que acabara de ser feita, e o aviso vermelho continuava aceso mesmo logo depois de exportar. Corrigido invertendo a ordem (marcar como salvo só depois do `audit()`) nos dois lugares.
- **Restauração de backup passou a refletir corretamente se o resultado está salvo ou não**: "Substituir estado atual" com um backup que já estava limpo deixa o estado como salvo (ele corresponde exatamente ao arquivo aberto); "Mesclar" sempre marca como não salvo, porque o resultado da mesclagem é uma combinação nova que ainda não existe em nenhum arquivo.
- **A ferramenta agora lê o backup para reapresentar os dados**, servindo como o único jeito de continuar de onde parou: a tela inicial vazia (sem nenhum relatório importado ainda nesta aba) ganhou um segundo botão, "Restaurar backup anterior", ao lado de "Importar relatórios novos" — nas telas de Visão geral e 2I. A restauração em si (validação de checksum, mesclar ou substituir) já existia desde a v1.12 e continua igual, só ficou mais visível como caminho normal de trabalho.
- Cópia de segurança automática antes de uma restauração (que antes ia para o IndexedDB) agora fica só em memória, pelo mesmo motivo — não sobrevive a um recarregamento de página, mas nunca sobreviveria de qualquer forma no modelo antigo se o usuário limpasse os dados do navegador.
- Adicionados 3 autotestes novos (75–77): `queueSave` sempre marca como não salvo, a ordem correta entre `audit()` e marcar como salvo (regressão do bug acima), e confirmação de que nenhuma função de IndexedDB restou no código. Total: 77 autotestes.

## Versão 1.12 (etapa 8 — backup/restauração, bloqueio local e diagnóstico)

Revisão do backup/restauração, do bloqueio local e da tela de Diagnóstico contra as seções 8, 9 e 10.7 da especificação (checklist de ~26 itens de diagnóstico). Resultado: a maior parte já estava coberta corretamente (checksum e formato validados antes de qualquer alteração, cópia de segurança automática antes de restaurar, mapeamento 2I bloqueado até confirmação explícita, cabeçalho obrigatório do CSV 2I validado, mesclagem sem duplicar por hash/id). Os itens abaixo eram lacunas reais e foram corrigidos.

- **Bug real corrigido:** a restauração de backup em modo "Mesclar" não recalculava quais snapshots ficam ativos/superados quando o backup trazia uma versão diferente do mesmo relatório (mesmo perfil, unidade e período, hash diferente). Isso não afetava o valor calculado (que já usava sempre o mais recente por data de importação), mas podia deixar dois snapshots "ativos" ao mesmo tempo na tela de Conferência e no Diagnóstico. Criada `recomputeSupersession()`, que reprocessa esse controle depois de toda restauração mesclada.
- **Novo diagnóstico: notação científica no prontuário.** Quando o `Cd Usu Cadsus` chega do Metabase já convertido em notação científica pelo Excel (ex.: `2.12E+15`, sinal de que os dígitos originais podem ter sido truncados), a ferramenta agora sinaliza um alerta crítico linha a linha na importação do CSV 2I, em vez de deixar passar silenciosamente. Não é confundido com o formato de milhar por vírgula (`2,115,998`), que continua sendo apenas limpo, sem gerar alerta.
- **Novo diagnóstico: resultado acima de 100%.** Antes só B2 tinha esse alerta. Agora todos os indicadores municipais (M1–M5) e federais (B1–B6) são verificados e sinalizados quando o resultado reconstruído passa de 100%.
- **Novo diagnóstico: denominador reconstruído igual a zero.** Quando há relatório aplicável importado para a competência mas o denominador reconstruído (procedimentos, atividades) é zero — diferente de "relatório ainda não importado" — a ferramenta agora avisa explicitamente em vez de só mostrar "—" no card.
- **Novo diagnóstico: denominador manual (M1/M3) divergente da sugestão do Metabase.** Já existia um link "usar sugestão" dentro do card; agora a divergência também aparece centralizada na tela de Diagnóstico.
- **Bloqueio local e backup cifrado passam a ser destacados como padrão recomendado quando há dados de gestantes (2I) no navegador** — tanto na tela de Configurações (aviso + botão de bloqueio em destaque) quanto no modal de backup (aviso ao abrir), conforme pedido pela especificação (seção 9: "quando houver dados de gestantes, destacar essas proteções como padrão recomendado").
- Conferido, sem necessidade de mudança: mapeamento explícito de "Consulta Saude Bucal" (bloqueia importação até confirmação, não presume nada); cabeçalhos obrigatórios do CSV 2I (erro específico nomeando o que falta); vírgula final do CSV mantendo colunas (teste 31); auditoria de ações 2I só grava IDs de episódio/cadastro, nunca nome/prontuário/telefone; duplicidade de episódio 2I com interpretações divergentes (`2I_DUPLICATE_CONFLICT`); cadastro manual possivelmente correspondente a registro do Metabase (`2I_MANUAL_MATCH`); quantidade por procedimento que não fecha com o subtotal usado no numerador (`M1_QUANTITY_VS_PEOPLE`/`M2_QUANTITY_VS_PEOPLE`); nenhum PDF/CSV bruto nem amostra de sessão entra no backup, só snapshots normalizados.
- Avaliado e mantido como está, por ser uma escolha de representação interna e não um requisito funcional: o JSON de backup usa uma cópia estruturada do estado interno da ferramenta em vez de replicar campo a campo o esquema de exemplo do texto da especificação (`schema_version`, `rulesets`, `snapshot_metadata` etc. nomeados exatamente assim); o conteúdo e as garantias (checksum, validação antes de aplicar, sem identificadores completos fora do necessário) são equivalentes.
- Não implementado, por ser de baixa prioridade dado o uso por uma só pessoa/unidade: resolução de conflito item a item ("manter ambos / substituir por mais novo / escolher manualmente") na restauração — hoje a escolha é só Mesclar-tudo ou Substituir-tudo, com deduplicação automática por hash/id dentro da mesclagem.
- Adicionados 3 autotestes novos (72–74): detecção de notação científica sem falso positivo em número com vírgulas, recomputo correto de qual snapshot fica ativo após uma restauração mesclada, e uma checagem de que a tela de Diagnóstico roda sem erros e cada item tem nível/código/mensagem válidos. Total: 74 autotestes.

## Versão 1.11 (ajustes no painel 2I, a pedido do usuário)

- **Removido o filtro de tipo de população** (Futuro/Presente do Metabase) do painel 2I — considerado informação desnecessária. O campo continua sendo lido do CSV internamente, mas não filtra mais nada; migração automática limpa o filtro de quem já tinha o estado antigo salvo.

A ferramenta agora remove vírgulas/pontos/espaços na importação e no cadastro manual, mantendo só os dígitos como texto (ex.: `2115998`) — sem afetar a identificação do episódio nem zeros à esquerda.
- **Novo filtro "gestação ativa/finalizada"**, determinado pela presença de data de parto registrada (com parto = finalizada; sem parto = ativa).

Um filtro "Mostrar só excluídas" permite conferir e reverter. Corrigido, ainda durante o desenvolvimento desta função, um bug de sobreposição visual em que o modal de confirmação de exclusão abria atrás da gaveta da gestante e ficava impossível de confirmar (a gaveta agora fecha antes do modal abrir, igual já acontecia para editar cadastro manual).
- Filtro de bairro não foi implementado a pedido do usuário (considerado desnecessário).
- Estendida a mescla de backup para também trazer as exclusões de gestantes salvas em outro arquivo, e o backup analítico (sem 2I) agora também limpa essa lista, fechando uma lacuna que só cobria acompanhamentos e cadastros manuais.
- Adicionados 3 autotestes novos (69–71) cobrindo a limpeza do prontuário, o cálculo de gestação ativa/finalizada e a reversibilidade da exclusão; o teste 50 (backup analítico) foi reforçado para também conferir a limpeza da lista de exclusões.

## Versão 1.10 (etapa 7 — 2I, gestantes)
